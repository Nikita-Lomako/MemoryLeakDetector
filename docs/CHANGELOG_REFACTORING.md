# История изменений после рефакторинга

## Удален проект MemoryLeakDetector.API

Проект API был полностью удален из solution. Весь функционал перенесен в другие проекты согласно принципам чистой архитектуры.

## Убрано ограничение на количество отслеживаемых процессов

### Изменения в Core:
- **MonitoringOptions.cs**: `MaxProcesses` теперь nullable (`int?`), по умолчанию `null`
- **ProcessMetricsCollector.cs**: Ограничение применяется только если `MaxProcesses` явно указан в конфигурации
- Система теперь отслеживает все доступные процессы на компьютере по умолчанию

### Изменения в конфигурации:
- Удален параметр `MaxProcesses` из `appsettings.json` и `appsettings.Development.json` в Service
- Теперь для ограничения количества процессов нужно явно указать `"MaxProcesses": <число>` в конфигурации

### Изменения в UI:
- **DashboardViewModel.cs**: Убрано ограничение `Math.Min(100, snapshots.Count)` для `TrackedProcesses`
- Теперь отображается реальное количество отслеживаемых процессов

## Добавлен функционал генерации отчетов в UI

### Новые компоненты:
1. **ReportsViewModel** (`UI/ViewModels/ReportsViewModel.cs`)
   - Управление генерацией отчетов
   - Выбор периода (FromDate, ToDate)
   - Команды для генерации JSON, HTML, PDF отчетов
   - Интеграция с диалогом сохранения файлов

2. **ReportsView** (`UI/Views/ReportsView.xaml`)
   - UI для выбора периода отчетов
   - Кнопки для генерации отчетов в разных форматах
   - Отображение статистики доступных данных

3. **Обновления навигации**:
   - Добавлен пункт "Reports" в навигационное меню
   - Зарегистрирован в DI контейнере
   - Добавлен DataTemplate для отображения

### Возможности:
- **JSON экспорт**: Структурированные данные для программной обработки
- **HTML экспорт**: Визуальный отчет с таблицами и стилями, открывается в браузере
- **PDF экспорт**: Документ для печати и архивирования с полной информацией

### Использование:
1. Откройте раздел "Reports" в навигационном меню
2. Выберите период для отчета (по умолчанию последние 7 дней)
3. Нажмите кнопку нужного формата (JSON, HTML или PDF)
4. Выберите место сохранения файла
5. Отчет будет сгенерирован и сохранен

## Архитектурные улучшения

- Все абстракции находятся в Core
- Реализации отчетов изолированы в UI (зависимость от QuestPDF только в UI)
- История мониторинга накапливается как в Service, так и в UI
- Полное разделение ответственности между слоями

## Технические детали

### Зависимости:
- UI проект теперь включает QuestPDF для генерации PDF отчетов
- Все остальные зависимости остались без изменений

### Производительность:
- Убрано ограничение в 100 процессов - система может отслеживать все процессы
- Рекомендуется настройка `IncludeSystemProcesses: false` для фильтрации системных процессов
- При необходимости можно установить `MaxProcesses` в конфигурации для ограничения нагрузки
