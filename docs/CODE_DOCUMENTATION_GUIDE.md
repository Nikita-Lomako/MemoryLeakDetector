# Руководство по документации кода

## Общие принципы

Код проекта документирован с использованием следующих подходов:

1. **XML-документация** для всех публичных API (классы, методы, свойства)
2. **Пояснительные комментарии** для сложных алгоритмов и бизнес-логики
3. **Комментарии к важным блокам кода** для понимания потока выполнения

## Структура комментариев

### XML-документация для классов

```csharp
/// <summary>
/// Краткое описание назначения класса.
/// </summary>
/// <remarks>
/// Дополнительные детали, если необходимо.
/// </remarks>
public class MyClass
{
}
```

### XML-документация для методов

```csharp
/// <summary>
/// Краткое описание того, что делает метод.
/// </summary>
/// <param name="parameter">Описание параметра</param>
/// <returns>Описание возвращаемого значения</returns>
/// <remarks>
/// Дополнительные детали реализации или примеры использования.
/// </remarks>
public ReturnType MyMethod(ParameterType parameter)
{
}
```

### Пояснительные комментарии

Используются для объяснения:
- Сложной бизнес-логики
- Алгоритмов вычислений
- Математических формул
- Оптимизаций производительности
- Важных решений дизайна

### Inline комментарии

Используются для пояснения:
- Сложных выражений
- Магических чисел (с объяснением)
- Workaround'ов для известных проблем
- Оптимизаций

## Рекомендации для остальных файлов

Все публичные классы, методы и свойства должны иметь XML-документацию.
Сложные алгоритмы должны иметь пояснительные комментарии.

Для генерации документации из XML комментариев используйте:
```bash
dotnet build /p:GenerateDocumentationFile=true
```
