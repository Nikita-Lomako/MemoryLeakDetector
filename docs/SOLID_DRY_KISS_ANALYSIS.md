## Анализ алгоритма детекции утечек

### Текущий алгоритм

Алгоритм использует **пороговый подход**:
1. Сравнивает текущие метрики с baseline (среднее значение)
2. Проверяет превышение порогов по проценту роста и абсолютному значению
3. Фиксирует утечку если хотя бы один порог превышен

### Потенциальные проблемы

#### 1. Отсутствие проверки тренда
**Проблема**: Алгоритм проверяет только одноразовое превышение порога, не учитывает устойчивый рост.

**Пример**: Процесс может временно увеличить память на 30% из-за временной нагрузки, а затем вернуться к норме. Это не утечка.

**Рекомендация**: Добавить проверку устойчивости превышения порога (например, утечка фиксируется только если порог превышен в N последних циклах подряд).

#### 2. Baseline может быть неточным для новых процессов
**Проблема**: Для новых процессов baseline строится быстро, и может быть неточным.

**Текущая защита**: `MinSamplesForLeakDetection` требует минимум 5 образцов.

**Рекомендация**: Рассмотреть увеличение минимального количества образцов или использовать медиану вместо среднего для более устойчивых результатов.

#### 3. Нет учета времени работы процесса
**Проблема**: Процесс, который только что запустился, может показать большой процент роста при инициализации, что нормально.

**Рекомендация**: Учитывать время работы процесса при принятии решения.

#### 4. False positives при всплесках нагрузки
**Проблема**: Временные всплески нагрузки могут быть ошибочно приняты за утечки.

**Рекомендация**: Использовать скользящее окно для проверки устойчивости роста.

### Что хорошо в текущем алгоритме

✅ **Пороговый подход** - простой и понятный
✅ **Базовая проверка достаточности данных** - защита от ложных срабатываний
✅ **Проверка как процента, так и абсолютного значения** - более точная детекция
✅ **Расширяемость** - легко добавить новые стратегии через интерфейс `ILeakDetectionStrategy`

## Тестирование детекции утечек

### Использование MemoryLeakTestApp

Создано тестовое приложение `MemoryLeakTestApp` для генерации различных типов утечек:

1. **Утечка managed памяти** (`[1]`)
   - Создает массивы байт по 10 MB каждую секунду
   - Имитирует типичную утечку в .NET приложениях

2. **Утечка таймеров** (`[2]`)
   - Создает таймеры, которые не освобождаются
   - Имитирует утечку ресурсов

3. **Комбинированная утечка** (`[3]`)
   - Сочетает оба типа утечек

4. **Постепенная утечка** (`[4]`)
   - Постепенно увеличивает потребление памяти
   - Имитирует медленную утечку

### Инструкция по тестированию

1. Запустите `MemoryLeakDetector.Service` для мониторинга
2. Запустите `MemoryLeakDetector.UI` для визуализации
3. Запустите `MemoryLeakTestApp` и выберите тип утечки
4. Наблюдайте за детекцией в UI
5. Проверьте отчеты в разделе "Reports"

### Ожидаемое поведение

- **Baseline строится**: Первые несколько циклов система накапливает baseline данные
- **Детекция начинается**: После превышения порогов должна появиться детекция утечки
- **Индикаторы**: В UI процесс должен быть помечен как "Leak"
- **Отчеты**: В отчетах должна быть информация об обнаруженной утечке
