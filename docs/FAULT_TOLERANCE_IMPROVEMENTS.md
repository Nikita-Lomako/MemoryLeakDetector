# Улучшения отказоустойчивости

## Проблема

При обнаружении утечек система создавала dump файлы синхронно в основном потоке мониторинга. Это приводило к:
- **Блокировке системы** при частых утечках (каждые 2-3 секунды)
- **Зависанию сервиса** при создании dump файлов для процессов с большим потреблением памяти
- **Отсутствию изоляции** - проблемы с одним процессом блокировали мониторинг всех остальных

## Реализованные решения

### 1. Асинхронное создание dump файлов ✅

**Проблема**: Создание dump файла занимает 1-1.5 секунды и блокировало основной цикл мониторинга.

**Решение**:
- Dump файлы теперь создаются асинхронно в фоновом потоке
- Основной цикл мониторинга не блокируется
- Используется `Task.Run` с `Task.Yield()` для немедленного возврата управления

**Настройка**:
```json
{
  "Monitoring": {
    "CreateDumpsAsync": true  // По умолчанию включено
  }
}
```

### 2. Rate Limiting для dump файлов ✅

**Проблема**: При частых утечках система пыталась создать dump файл каждые 2-3 секунды.

**Решение**:
- Создан `RateLimitedStackTraceProvider` - обертка с ограничением частоты
- По умолчанию не более одного dump файла в минуту на процесс
- Автоматическая очистка истории для неактивных процессов

**Настройка**:
```json
{
  "Monitoring": {
    "DumpCreationMinIntervalSeconds": 60  // Минимум 60 секунд между dump'ами для одного процесса
  }
}
```

**Особые значения**:
- `0` - без ограничений (не рекомендуется)
- `-1` - полностью отключить создание dump файлов
- `> 0` - минимальный интервал в секундах

### 3. Изоляция сбоев ✅

**Проблема**: Ошибка при анализе одного процесса блокировала обработку остальных.

**Решение**:
- Каждый процесс обрабатывается в отдельном try-catch блоке
- Ошибки логируются, но не прерывают цикл мониторинга
- Ошибки создания dump файлов изолированы и не влияют на мониторинг
- Добавлен таймаут для синхронного создания dump (10 секунд)

**Код**:
```csharp
foreach (var snapshot in snapshots)
{
    try
    {
        // Анализ процесса
    }
    catch (Exception ex)
    {
        errors++;
        _logger.LogError(ex, "Failed to analyze process...");
        // Продолжаем обработку других процессов
    }
}
```

### 4. Управление фоновыми задачами ✅

**Проблема**: Накопление незавершенных задач создания dump файлов.

**Решение**:
- Отслеживание активных задач создания dump файлов
- Автоматическая очистка завершенных задач после каждого цикла
- Логирование ошибок в фоновых задачах

## Архитектурные улучшения

### RateLimitedStackTraceProvider

Новый класс-обертка над `IStackTraceProvider`:
- Ограничивает частоту создания dump файлов
- Хранит историю последнего dump для каждого процесса
- Автоматически очищает историю для неактивных процессов
- Полностью прозрачен для остального кода (реализует `IStackTraceProvider`)

### MonitoringCoordinator

Улучшения:
- Асинхронное создание dump файлов (fire-and-forget)
- Изоляция ошибок для каждого процесса
- Таймаут для синхронного создания dump
- Автоматическая очистка завершенных задач

## Настройки в appsettings.json

```json
{
  "Monitoring": {
    "DumpCreationMinIntervalSeconds": 60,  // Минимум 60 секунд между dump'ами
    "CreateDumpsAsync": true                 // Асинхронное создание
  }
}
```

## Рекомендации

### Для production окружения:
```json
{
  "DumpCreationMinIntervalSeconds": 300,  // 5 минут между dump'ами
  "CreateDumpsAsync": true
}
```

### Для разработки/тестирования:
```json
{
  "DumpCreationMinIntervalSeconds": 30,   // 30 секунд для более быстрого тестирования
  "CreateDumpsAsync": true
}
```

### Для отключения dump файлов (если не нужны):
```json
{
  "DumpCreationMinIntervalSeconds": -1    // Полностью отключить
}
```

## Результаты

### До улучшений:
- ❌ Система блокировалась при частых утечках
- ❌ Один проблемный процесс мог остановить весь мониторинг
- ❌ Создание dump файлов занимало 1-1.5 секунды в основном потоке
- ❌ Нет защиты от переполнения disk пространства dump файлами

### После улучшений:
- ✅ Основной цикл мониторинга не блокируется
- ✅ Изоляция ошибок - проблемы с одним процессом не влияют на другие
- ✅ Rate limiting предотвращает создание слишком частых dump файлов
- ✅ Асинхронное создание dump не влияет на производительность мониторинга
- ✅ Автоматическая очистка ресурсов (завершенные задачи, неактивные процессы)

## Производительность

**Влияние на основной цикл**:
- **До**: 1-1.5 секунды задержки при создании dump
- **После**: < 1 мс (задача создается асинхронно)

**Потребление памяти**:
- Минимальное увеличение за счет отслеживания активных задач
- Автоматическая очистка завершенных задач
- История rate limiting ограничена активными процессами

## Тестирование

Для проверки отказоустойчивости:
1. Запустите `MemoryLeakTestApp` с типом утечки [1]
2. Наблюдайте за логами Service
3. Убедитесь, что dump файлы создаются не чаще раза в минуту
4. Убедитесь, что основной цикл мониторинга продолжает работать с нормальной скоростью
5. Проверьте, что другие процессы продолжают мониториться

## Следующие шаги (опционально)

1. **Ограничение размера dump файлов** - предотвращение переполнения disk
2. **Автоматическое удаление старых dump файлов** - управление disk пространством
3. **Приоритизация процессов** - более важные процессы получают dump файлы чаще
4. **Сжатие dump файлов** - экономия disk пространства
