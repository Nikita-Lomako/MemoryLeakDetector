# Улучшения алгоритма детекции утечек

## Реализованные улучшения

### 1. Использование медианы вместо среднего для baseline ✅

**Проблема**: Среднее значение чувствительно к выбросам, что может давать неточный baseline.

**Решение**: 
- Добавлено вычисление медианы для всех метрик (Working Set, Virtual Memory, Handles)
- Медиана более устойчива к временным всплескам
- Baseline теперь содержит и среднее, и медиану
- По умолчанию используется медиана (`UseMedianForBaseline: true`)

**Преимущества**:
- Более точный baseline для процессов с переменной нагрузкой
- Меньше false positives от временных всплесков
- Сохранена совместимость (среднее значение также доступно)

### 2. Проверка устойчивости утечки ✅

**Проблема**: Одноразовое превышение порога может быть временным всплеском, а не реальной утечкой.

**Решение**:
- Создан `LeakSuspicionTracker` для отслеживания истории подозрений
- Утечка фиксируется только если порог превышен в N последовательных циклах (по умолчанию 3)
- Временные всплески не приводят к false positives

**Настройка**:
```json
{
  "Monitoring": {
    "LeakConfirmationCycles": 3  // Количество циклов для подтверждения
  }
}
```

**Поведение**:
- Первое превышение порога → подозрение регистрируется
- Если подозрение подтверждается в следующих циклах → утечка фиксируется
- Если подозрение не подтверждается → подозрение сбрасывается

### 3. Трендовый анализ ✅

**Проблема**: Постепенные медленные утечки могут не превышать порог за один цикл, но показывать устойчивый рост.

**Решение**:
- Добавлено вычисление тренда Working Set (скорость роста в MB/цикл)
- Используется линейная регрессия для определения наклона тренда
- Тренд учитывается при детекции как дополнительный индикатор

**Настройка**:
```json
{
  "Monitoring": {
    "EnableTrendAnalysis": true  // Включить трендовый анализ
  }
}
```

**Поведение**:
- Если тренд показывает рост > 5 MB/цикл, добавляется индикатор
- Тренд вычисляется на основе последних N образцов baseline
- Помогает обнаруживать медленные постепенные утечки

## Технические детали

### ProcessBaseline - расширенная модель

Добавлены новые свойства:
```csharp
public double MedianWorkingSetMb { get; }      // Медиана Working Set
public double MedianVirtualMemoryMb { get; }   // Медиана Virtual Memory
public double MedianHandleCount { get; }       // Медиана Handles
public double? TrendWorkingSetMb { get; }      // Тренд Working Set (MB/цикл)
```

### LeakSuspicionTracker

Новый класс для отслеживания истории подозрений:
- Хранит историю последних N подозрений для каждого процесса
- Проверяет подтверждение утечки (все последние N циклов показывали подозрение)
- Автоматически очищается для неактивных процессов

### ThresholdLeakDetectionStrategy - улучшенная логика

**Обновленный алгоритм**:
1. Проверка достаточности baseline данных
2. Вычисление метрик с использованием медианы (если включена)
3. Обнаружение индикаторов утечки (превышение порогов)
4. Регистрация подозрения в трекере
5. Проверка устойчивости (подтверждение в N циклах)
6. Анализ тренда (если включен)
7. Формирование финального решения

## Настройки в appsettings.json

```json
{
  "Monitoring": {
    "PollingIntervalMilliseconds": 2000,
    "BaselineWindow": 120,
    "WorkingSetLeakThresholdPercent": 25.0,
    "WorkingSetLeakThresholdMb": 150.0,
    "VirtualMemoryLeakThresholdPercent": 30.0,
    "HandleLeakThresholdPercent": 40.0,
    "MinSamplesForLeakDetection": 5,
    "IncludeSystemProcesses": false,
    
    // Новые настройки:
    "LeakConfirmationCycles": 3,      // Количество циклов для подтверждения утечки
    "UseMedianForBaseline": true,      // Использовать медиану вместо среднего
    "EnableTrendAnalysis": true        // Включить трендовый анализ
  }
}
```

## Влияние на детекцию

### До улучшений:
- ❌ False positives при временных всплесках
- ❌ Неточный baseline для процессов с переменной нагрузкой
- ❌ Пропуск медленных постепенных утечек

### После улучшений:
- ✅ Меньше false positives благодаря проверке устойчивости
- ✅ Более точный baseline благодаря медиане
- ✅ Обнаружение медленных утечек благодаря трендовому анализу
- ✅ Более надежная детекция в целом

## Производительность

**Дополнительные вычисления**:
- Медиана: O(n log n) для N образцов, но N ограничено BaselineWindow (обычно 120)
- Тренд: O(n) для линейной регрессии
- История подозрений: O(1) операции вставки/проверки

**Влияние**: Минимальное, так как:
- Вычисления выполняются только для активных процессов
- Количество образцов ограничено BaselineWindow
- Используются эффективные структуры данных (Queue, Dictionary)

## Рекомендации по настройке

### Для быстрой детекции (больше false positives):
```json
{
  "LeakConfirmationCycles": 1,
  "MinSamplesForLeakDetection": 3
}
```

### Для точной детекции (меньше false positives):
```json
{
  "LeakConfirmationCycles": 5,
  "MinSamplesForLeakDetection": 10,
  "UseMedianForBaseline": true,
  "EnableTrendAnalysis": true
}
```

### Для медленных постепенных утечек:
```json
{
  "EnableTrendAnalysis": true,
  "WorkingSetLeakThresholdPercent": 15.0,  // Более низкий порог
  "LeakConfirmationCycles": 5              // Больше циклов для подтверждения
}
```

## Обратная совместимость

Все изменения обратно совместимы:
- Существующие конфигурации продолжат работать
- Новые опции имеют разумные значения по умолчанию
- Среднее значение все еще доступно, если медиана не используется
