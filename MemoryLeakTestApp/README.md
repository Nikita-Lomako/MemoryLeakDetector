# Memory Leak Test Application

Тестовое приложение для генерации различных типов утечек памяти. Используется для тестирования функциональности **MemoryLeak Detector**.

## Назначение

Это приложение создает намеренные утечки памяти различных типов, что позволяет:
- Тестировать алгоритмы детекции утечек
- Проверять точность работы детектора
- Визуализировать работу системы мониторинга
- Валидировать отчеты и предупреждения

## Типы утечек

### 1. Утечка Managed памяти (`[1]`)
- Создает массивы байт по 10 MB каждую секунду
- Имитирует типичную утечку в .NET приложениях
- Память не освобождается, что приводит к постепенному росту Working Set

### 2. Утечка таймеров (`[2]`)
- Создает таймеры, которые не освобождаются
- Имитирует утечку системных ресурсов (handles)
- Приводит к росту количества handles процесса

### 3. Комбинированная утечка (`[3]`)
- Сочетает оба типа утечек одновременно
- Более реалистичный сценарий для тестирования

### 4. Постепенная утечка (`[4]`)
- Постепенно увеличивает размер утечки (от 5 до 50 MB)
- Имитирует медленную, постепенную утечку
- Полезно для тестирования детекции медленных утечек

## Использование

### Запуск

1. Скомпилируйте проект:
   ```bash
   dotnet build
   ```

2. Запустите приложение:
   ```bash
   dotnet run
   ```

### Команды

После запуска выберите тип утечки:
- `[1]` - Утечка managed памяти
- `[2]` - Утечка таймеров
- `[3]` - Комбинированная утечка
- `[4]` - Постепенная утечка
- `[q]` - Выход и очистка ресурсов

### Тестирование с MemoryLeak Detector

1. **Запустите Service**:
   ```bash
   cd MemoryLeakDetector.Service
   dotnet run
   ```

2. **Запустите UI**:
   ```bash
   cd MemoryLeakDetector.UI
   dotnet run
   ```

3. **Запустите тестовое приложение**:
   ```bash
   cd MemoryLeakTestApp
   dotnet run
   ```

4. **Наблюдайте**:
   - В UI перейдите в раздел "Processes"
   - Найдите процесс `MemoryLeakTestApp`
   - Через несколько циклов мониторинга должна появиться детекция утечки
   - Процесс будет помечен как "Leak"

### Ожидаемое поведение

- **Первые 5-10 циклов**: Система строит baseline для процесса
- **После превышения порогов**: Процесс должен быть помечен как подозрительный
- **В Analytics**: Можно увидеть графики роста памяти
- **В Reports**: Можно сгенерировать отчет с информацией об утечке

## Настройка порогов детекции

По умолчанию детектор использует следующие пороги (в `appsettings.json`):
- `WorkingSetLeakThresholdPercent`: 25%
- `WorkingSetLeakThresholdMb`: 150 MB
- `VirtualMemoryLeakThresholdPercent`: 30%
- `HandleLeakThresholdPercent`: 40%

Для более быстрого тестирования можно уменьшить пороги:
```json
{
  "Monitoring": {
    "WorkingSetLeakThresholdPercent": 10.0,
    "WorkingSetLeakThresholdMb": 50.0,
    "MinSamplesForLeakDetection": 3
  }
}
```

## Безопасность

⚠️ **Важно**: Это тестовое приложение намеренно создает утечки памяти.
- Запускайте только на тестовых системах
- Не запускайте на production серверах
- Следите за использованием памяти системы
- Используйте `[q]` для корректного завершения и очистки ресурсов

## Очистка

При завершении приложения (нажатие `[q]` или `Ctrl+C`):
- Все утечки очищаются
- Выполняется принудительный сбор мусора
- Ресурсы освобождаются

## Примечания

- Приложение продолжает работать до явного завершения
- Для каждого типа утечки создается отдельный поток
- Статистика выводится в консоль
- Можно запускать несколько экземпляров одновременно для тестирования множественных процессов
