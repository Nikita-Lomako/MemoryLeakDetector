# ВВЕДЕНИЕ

Утечки памяти являются одной из наиболее сложных проблем в разработке программного обеспечения. Они приводят к постепенному исчерпанию доступной оперативной памяти, снижению производительности приложений и, в конечном итоге, к их аварийному завершению. Особенно критичны утечки памяти для долгоработающих серверных приложений и систем реального времени.

**Цель курсовой работы** — разработка программного модуля «MemoryLeak Detector» для обнаружения и анализа утечек памяти в работающих процессах Windows.

**Предусмотрено решение следующих задач:**
1. Реализация мониторинга процессов в реальном времени (RAM, Virtual Memory, Handles)
2. Разработка алгоритмов обнаружения утечек на основе статистического анализа
3. Реализация сравнения с baseline-показателями для выявления аномалий
4. Создание механизма привязки утечек к информации о процессе
5. Разработка UI для визуализации данных мониторинга

В данной работе предусмотрено три главы.

**В первой главе** «Анализ предметной области» дается обзор существующих решений для обнаружения утечек памяти, описываются их достоинства и недостатки.

**Во второй главе** «Проектирование системы» описывается архитектура приложения, алгоритмы обнаружения утечек и проектирование пользовательского интерфейса.

**В третьей главе** «Программная реализация» приведены ключевые части исходного кода, описание структуры проекта и демонстрация работы приложения.

# ГЛАВА 1: АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ

## 1.1. Постановка задач для реализации приложения

Согласно техническому заданию, программный модуль должен обеспечивать:

**Базовый функционал:**
- Мониторинг процессов в реальном времени (RAM, Virtual Memory, Handles)
- Обнаружение утечек памяти через статистический анализ
- Сравнение с baseline-показателями
- Привязка утечек к информации о процессе
- Поддержка Windows 10/11

**Требования к производительности:**
- Задержка внедрения в процесс: ≤ 100 ms
- Нагрузка на CPU: ≤ 5%
- Потребление памяти модулем: ≤ 50 MB
- Поддержка до 100 процессов одновременно

**Требования к надежности:**
- Автоматическое переподключение к процессам
- Изоляция сбоев (один упавший процесс не влияет на другие)
- Не требует прав администратора для user-процессов

## 1.2. Обзор существующих решений

### Visual Studio Diagnostic Tools

Встроенные инструменты Visual Studio для профилирования памяти.

**Достоинства:**
- Глубокая интеграция с IDE
- Детальный анализ managed и native памяти
- Поддержка snapshot-сравнения

**Недостатки:**
- Требует запуска из Visual Studio
- Высокое потребление ресурсов
- Не подходит для production-мониторинга

### dotMemory (JetBrains)

Профессиональный профилировщик памяти для .NET приложений.

**Достоинства:**
- Детальный анализ объектов в памяти
- Визуализация retention paths
- Автоматическое обнаружение типичных утечек

**Недостатки:**
- Коммерческая лицензия
- Требует остановки процесса для анализа
- Не работает в режиме реального времени

### PerfView

Бесплатный инструмент от Microsoft для анализа производительности.

**Достоинства:**
- Низкое потребление ресурсов
- Анализ GC pressure
- Поддержка ETW событий

**Недостатки:**
- Сложный интерфейс
- Требует экспертных знаний
- Не автоматизирован

## 1.3. Выводы по главе 1

Анализ существующих решений показал, что на рынке отсутствует легковесный инструмент для автоматического мониторинга утечек памяти в реальном времени с низким потреблением ресурсов. Разрабатываемое приложение призвано заполнить эту нишу, предоставляя:

- Автоматический мониторинг без участия пользователя
- Низкое потребление ресурсов (≤ 50 MB)
- Современный UI с визуализацией трендов
- Клиент-серверную архитектуру для гибкости развертывания

## 2.2. Проектирование алгоритмов обнаружения утечек

### Алгоритм на основе baseline

1. **Сбор baseline** — накопление истории метрик процесса (последние N измерений)
2. **Вычисление эталона** — расчет медианы и среднего значения
3. **Сравнение** — текущие метрики сравниваются с baseline
4. **Подтверждение** — утечка подтверждается при превышении порога в N последовательных циклах

### Пороговые значения

| Метрика | Порог (%) | Порог (абс.) |
|---------|-----------|--------------|
| Working Set | 14% | 50 MB |
| Virtual Memory | 24% | — |
| Handles | 20% | — |

### Трендовый анализ

Для обнаружения постепенных утечек используется линейная регрессия:
- Вычисляется наклон линии тренда (slope)
- Если тренд > 10 MB/цикл — фиксируется утечка

## 2.3. Построение интерфейса пользователя

### Dashboard (Главная панель)

Отображает:
- Общее количество отслеживаемых процессов
- Количество активных предупреждений об утечках
- Топ-4 процесса по потреблению памяти
- Общий тренд потребления памяти

### Processes (Список процессов)

Таблица со всеми отслеживаемыми процессами:
- Имя процесса и PID
- Working Set, Virtual Memory, Handles
- CPU usage и GC метрики
- Флаг подозрения на утечку

### Analytics (Аналитика)

Графики и детальный анализ:
- График Working Set по каждому процессу (индивидуальные линии)
- Список процессов с подозрением на утечку
- Рекомендации по анализу

## 2.4. Выводы по главе 2

В процессе проектирования была разработана трехслойная архитектура с четким разделением ответственности. Алгоритм обнаружения утечек основан на статистическом анализе и baseline-сравнении, что обеспечивает баланс между чувствительностью и устойчивостью к false positives.

## 3.4. Работа с приложением

### Запуск приложения

1. Сначала запускается `MemoryLeakDetector.Service` — фоновый сервис мониторинга
2. Затем запускается `MemoryLeakDetector.UI` — графический интерфейс
3. UI автоматически подключается к Service через Named Pipe

### Интерфейс приложения

**Dashboard** показывает общую статистику системы и топ потребителей памяти.

**Processes** отображает таблицу всех процессов с возможностью поиска и фильтрации.

**Analytics** содержит:
- График Working Set по процессам (каждый процесс — отдельная линия своего цвета)
- Список процессов с подозрением на утечку
- Рекомендации по анализу

### Пример работы

При обнаружении утечки:
1. Система фиксирует превышение порога в нескольких циклах подряд
2. Процесс отмечается как подозрительный
3. В консоли Service выводится предупреждение
4. В UI процесс выделяется в списке утечек
5. Генерируются рекомендации по анализу
